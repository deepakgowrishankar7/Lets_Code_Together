Exception Handling in Python

Exception Handling is the process of handling runtime errors so the program continues executing gracefully instead of crashing.

What is an Exception?

An exception is an unexpected event that occurs during program execution.

print(10/0)
ZeroDivisionError

Why Exception Handling?

  • Prevents program crashes
  • Improves reliability
  • Provides better user experience
  • Handles invalid input safely
  • Protects application flow

Program Without Exception Handling

num1 = 10 num2 = 0 print(num1/num2) print("Program Ended")

Basic try-except

try: print(10/0) except: print("Error Occurred")
Error Occurred

Handling Specific Exceptions

try: print(10/0) except ZeroDivisionError: print("Cannot divide by zero")

Multiple Exceptions

try: numbers=[10,20,30] print(numbers[5]) except IndexError: print("Invalid Index") except ValueError: print("Invalid Value")

Multiple Exceptions in One Block

try: value=int("abc") except (ValueError,TypeError): print("Conversion Error")

else Block

try: print(10/2) except: print("Error") else: print("Success")

finally Block

try: print(10/2) finally: print("Always Executes")

Exception Object

try: print(10/0) except ZeroDivisionError as e: print(e)

Nested Try Blocks

try: try: print(10/0) except ZeroDivisionError: print("Inner Exception") except: print("Outer Exception")

File Exception Example

try: file=open("sample.txt","r") except FileNotFoundError: print("File Not Found")

Raise Keyword

age=-5 if age < 0: raise ValueError("Age cannot be negative")

Custom Exceptions

class InvalidAgeError(Exception): pass age=-1 if age < 0: raise InvalidAgeError("Invalid Age")

ATM Custom Exception Project

class InsufficientBalance(Exception): pass balance=1000 withdraw=2000 if withdraw > balance: raise InsufficientBalance("Insufficient Balance")

Login Validation Example

username="" try: if username=="": raise ValueError("Username Cannot Be Empty") except ValueError as e: print(e)

Best Practices

  • Handle specific exceptions
  • Use finally for cleanup
  • Avoid empty except blocks
  • Log errors in real projects
  • Create custom exceptions when needed
