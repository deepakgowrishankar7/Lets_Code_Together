Python Environments, Pip & Packaging

Isolated Virtual Environments prevent dependency conflicts across projects, while standard packaging tools like pip and pyproject.toml manage dependencies.

1. Managing Virtual Environments (`venv`)

# Step 1: Create virtual environment named 'venv'
python -m venv venv

# Step 2: Activate virtual environment
# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# macOS / Linux:
source venv/bin/activate

# Step 3: Deactivate when finished
deactivate

2. Package Management with `pip` & `requirements.txt`

# Install third-party packages
pip install requests pandas

# Save exact environment dependencies to file
pip freeze > requirements.txt

# Install dependencies from requirements file on a new machine
pip install -r requirements.txt

3. Modern Python Packaging (`pyproject.toml`)

Modern Python projects use pyproject.toml as the unified build specification file (replacing legacy `setup.py`). 

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[project]
name = "my_custom_package"
version = "0.1.0"
authors = [
    { name="Developer Name", email="dev@example.com" },
]
description = "A high-performance utility library"
readme = "README.md"
requires-python = ">=3.10"
dependencies = [
    "requests>=2.28.0",
]

Building Wheel Packages:

pip install build
python -m build # Generates dist/my_custom_package-0.1.0-py3-none-any.whl
