Java Strings

Beginner Read Time: 12 mins

1. The Real-World Analogy: Library Book Sharing

Imagine a school library that has only one copy of "The Hobbit". Three students want to read it. Instead of buying three separate books, the library registers all three students to share that single physical copy.

In Java, String literals work the same way. Since strings are immutable (cannot change), the JVM shares a single copy of a string literal among multiple variables inside the String Constant Pool to save memory.

2. The String Constant Pool & Immutability

Java Strings are **immutable**, meaning their value cannot be modified once created in the Heap. When you do: String s = "Hello"; s = s + " World";, the original `"Hello"` string is NOT changed. Instead, a brand new string `"Hello World"` is created in the Heap, and the reference variable s is updated to point to it.

The String Constant Pool (SCP) is a special memory area inside the Heap. Liters are cached here. If you create a string that already exists in the pool, Java simply redirects your variable to point to the existing instance instead of creating a new object.

⚠️ Warning: The == vs .equals() Trap!

Never use == to compare strings. The == operator compares **memory reference addresses** (whether they point to the exact same memory location). To compare the **actual characters/content** of strings, you must always use .equals().

3. String vs. StringBuilder vs. StringBuffer

When modifying text frequently (like in loops), using String is slow because it creates a new object on every edit. We use mutable classes instead:

Property String StringBuilder StringBuffer
Mutability Immutable (Cannot change) Mutable (Can modify) Mutable (Can modify)
Thread Safety Safe (Read-only) Not Thread-Safe (Fastest) Thread-Safe (Synchronized, slower)
Memory Area Heap & String Pool Heap only Heap only

💻 Example Code & Line-by-Line Breakdown

public class StringDemo {
    public static void main(String[] args) {
        String s1 = "Java"; // Inside String Pool
        String s2 = new String("Java"); // Forced new object on Heap

        System.out.println(s1 == s2);      // false (different memory locations)
        System.out.println(s1.equals(s2)); // true (same character content)
        
        // Efficient text builder
        StringBuilder sb = new StringBuilder("Hello");
        sb.append(" World");
        System.out.println(sb.toString()); // "Hello World"
    }
}

Line-by-Line Breakdown:

  • String s1 = "Java";: Places `"Java"` in the String Pool and references it.
  • String s2 = new String("Java");: Forces the JVM to bypass the pool and create a new String object directly on the general Heap.
  • s1 == s2: Evaluates to false because s1 references the Pool, while s2 references a different address on the general Heap.
  • sb.append(" World");: Modifies the original internal character array of `sb` directly without creating any intermediate string objects.

💬 Topic Interview Prep Q&A

Google Meta

Q1: Why are Strings immutable in Java?

A: Immutability guarantees: 1. **Memory efficiency:** The String Pool can share literals. 2. **Security:** Strings are widely used for databases, file paths, and network credentials; immutability prevents malicious changes. 3. **Thread Safety:** Multiple threads can read a string simultaneously without synchronization issues.

Microsoft

Q2: What is the difference between String s = "abc" and String s = new String("abc")?

A: The first creates a string in the String Pool. If `"abc"` already exists, it reuses the pool reference. The second syntax always allocates a new String object on the main Heap, plus creates the literal in the Pool if it's not already present, resulting in duplicate memory allocation.
