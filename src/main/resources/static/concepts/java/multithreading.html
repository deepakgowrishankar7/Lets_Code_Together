Multithreading & Concurrency

Advanced Read Time: 15 mins

1. The Real-World Analogy: Kitchen Chefs

Imagine a busy restaurant kitchen. If you have only one chef (single thread), they must chop vegetables, boil pasta, and grill steak one after another. Food comes out slowly. If you hire 3 chefs (multithreading), one chops, one boils, and one grills simultaneously.

In Java, Multithreading allows the CPU to run multiple paths of execution (threads) at the same time, maximizing hardware resources and completing tasks faster.

2. Creating Threads: Thread Class vs. Runnable

There are two primary ways to create an executable thread in Java:

  • Extending the Thread Class: Subclassing Thread directly. (Cannot inherit from any other class due to single inheritance).
  • Implementing the Runnable Interface: Cleaner, more flexible, and lets you inherit from another base class. (Preferred practice).
// Implementing Runnable
class Worker implements Runnable {
    public void run() {
        System.out.println("Thread running: " + Thread.currentThread().getName());
    }
}
// Execution
Thread t = new Thread(new Worker());
t.start(); // Spawns the thread (do not call run() directly!)

⚠️ Warning: Deadlocks & Race Conditions!

  • Race Condition: When multiple threads access shared mutable data simultaneously without coordination, resulting in corrupted values.
  • Deadlock: When Thread A holds Lock 1 and waits for Lock 2, while Thread B holds Lock 2 and waits for Lock 1. Both threads wait forever, freezing the application.

3. Synchronization & Thread Safety

To prevent race conditions, we coordinate thread execution:

  • Synchronized Block/Method: Locks the shared object. Only one thread can enter the synchronized section at a time.
  • Volatile Keyword: Forces the CPU to read and write variables directly from main memory instead of caching them in local CPU registers, ensuring immediate **visibility** across threads.
  • ReentrantLock: A more flexible, manual locking mechanism supporting try-lock and timeouts.

💻 Example Code: Thread Synchronization

public class CounterDemo {
    private int count = 0;

    // 'synchronized' locks the CounterDemo instance so only one thread can increment at a time
    public synchronized void increment() {
        count++;
    }

    public static void main(String[] args) throws InterruptedException {
        CounterDemo demo = new CounterDemo();
        
        Runnable task = () -> {
            for (int i = 0; i < 1000; i++) demo.increment();
        };

        Thread t1 = new Thread(task);
        Thread t2 = new Thread(task);
        
        t1.start();
        t2.start();
        t1.join(); // Wait for t1 to finish
        t2.join(); // Wait for t2 to finish

        System.out.println("Final Count: " + demo.count); // Output is guaranteed to be 2000
    }
}

Line-by-Line Breakdown:

  • public synchronized void increment(): If two threads call this method simultaneously, one is forced to wait in a Blocked state until the other completes.
  • t1.start();: Asynchronously schedules the thread runner. (Calling t1.run() would execute it synchronously inside the main thread, defeating the purpose of multithreading).
  • t1.join();: Forces the calling thread (main thread) to halt until thread t1 terminates.

💬 Topic Interview Prep Q&A

Q1: What is the difference between Thread.start() and Thread.run()?

A: start() is used to spawn a new asynchronous operating system thread and runs the code inside the run() method on that new thread context. Calling run() directly does not spawn a new thread; it simply executes the code synchronously inside the current thread like a normal method call.

Oracle

Q2: What is the volatile keyword in Java?

A: The volatile keyword tells the compiler and JVM that the variable's value must always be read from and written to main memory, bypassing local CPU caches. This guarantees thread visibility but does not guarantee operations are atomic.
