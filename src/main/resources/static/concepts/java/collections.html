Java Collections Framework

Intermediate Read Time: 12 mins

1. The Real-World Analogy: Container Organizers

Imagine organizing different objects in your room. Depending on what you are organizing, you choose different tools:

  • A Notebook (List): Stores items sequentially. You can write the same word multiple times, and the order matters.
  • A Jar of Marbles (Set): Holds unique items. If you drop two blue marbles inside, they just mix together; order doesn't matter, and duplicates are impossible.
  • A Rolodex Contacts Book (Map): Associates a unique key (Name) with a value (Phone number). You look up the phone number by indexing the name.

2. Key Collections Hierarchy

The collections framework resides in java.util. Primitives cannot go directly into collections; you must use wrapper classes (like Integer).

Interface Common Class Order Preserved? Allows Duplicates? Internal Data Structure
List ArrayList ✅ Yes ✅ Yes Dynamic resizeable Array
LinkedList ✅ Yes ✅ Yes Doubly Linked List nodes
Set HashSet ❌ No ❌ No HashMap (using key indices)
TreeSet ✅ Yes (Sorted) ❌ No Self-balancing Red-Black Tree
Map HashMap ❌ No Key: ❌ No, Value: ✅ Yes Hash buckets array + Node lists
TreeMap ✅ Yes (Sorted) Key: ❌ No, Value: ✅ Yes Self-balancing Red-Black Tree

⚠️ Warning: ConcurrentModificationException!

If you try to modify a collection (like adding or removing items) directly inside a standard for-each loop, Java's iterator will detect a structural modification mismatch and throw a ConcurrentModificationException. To edit safe, use an explicit Iterator or removeIf().

💻 Example Code: HashMap Internal Access

import java.util.*;

public class MapDemo {
    public static void main(String[] args) {
        Map<String, Integer> inventory = new HashMap<>();
        inventory.put("Apples", 50);
        inventory.put("Bananas", 20);
        inventory.put("Apples", 75); // Overwrites key "Apples" with new value
        
        for (Map.Entry<String, Integer> entry : inventory.entrySet()) {
            System.out.println(entry.getKey() + " -> " + entry.getValue());
        }
    }
}

Line-by-Line Breakdown:

  • Map<String, Integer>: Declares key datatype as String and value datatype as wrapper Integer.
  • inventory.put("Apples", 75);: Since keys must be unique, Java hashes `"Apples"`, resolves the bucket index, checks for equality, and updates the value from 50 to 75.
  • inventory.entrySet(): Returns a set representation of key-value mapping nodes to allow clean loop iteration.

💬 Topic Interview Prep Q&A

Google Meta

Q1: How does HashMap handle key hashing and collisions?

A: HashMap uses the key's hashCode() to locate the bucket array index. If multiple keys hash to the same bucket (collision), they are chained in a LinkedList. If bucket size exceeds 8, the chain converts to a Balanced Tree (Red-Black Tree) to keep retrieval speed at O(log n) instead of O(n).

Microsoft

Q2: What is the equals() and hashCode() contract?

A: If two objects are equal (determined by equals()), they MUST return the exact same integer value for hashCode(). If you override one, you must override both, otherwise custom objects will fail to locate keys correctly inside HashMaps and HashSets.
