Object-Oriented Programming (OOP) Pillars

Intermediate Read Time: 15 mins

1. The Four Pillars of OOP

Object-Oriented Programming is a paradigm that models software around real-world objects. In Java, this structure rests on **Four Pillars**:

🛡️ 1. Encapsulation

Hiding data by declaring fields private and exposing them only through public getters/setters. (Analogy: Medicine capsule protecting its ingredients).

🌳 2. Inheritance

Reusing code by letting child classes inherit attributes and methods from parent classes using extends. (Analogy: Child inheriting family traits).

🎭 3. Polymorphism

Allowing objects to take multiple forms (overriding parent methods). (Analogy: A person acting differently at work vs. at home).

🔌 4. Abstraction

Hiding background complexity and showing only relevant interaction signatures. (Analogy: Operating a TV remote without knowing the circuit design).

⚠️ Warning: Method Overloading vs. Overriding!

  • Overloading (Compile-time): Same method name, different parameters inside the same class.
  • Overriding (Runtime): Re-defining a parent method inside a subclass with the *exact same* signature. Add `@Override` to catch compilation mismatches.

2. Deep Dive: Interfaces vs. Abstract Classes

Both support Abstraction, but they differ in purpose and capability:

Property Abstract Class Interface
Inheritance model Single inheritance (Class can only extend one class). Multiple inheritance (Class can implement many interfaces).
Instance Variables Can have instance fields (state). Variables are implicitly public static final (constants).
Methods Can have both abstract and concrete methods. Abstract methods (Java 8+ supports default & static methods).
Constructor Can have constructors (for subclasses). Cannot have constructors.

💻 Example Code & Line-by-Line Breakdown

// 1. Abstraction: Contract definition
interface Animal {
    void makeSound(); // Implicitly public abstract
}

// 2. Inheritance: Dog extends generic class characteristics
class Dog implements Animal {
    // 3. Encapsulation: Private state hidden
    private String name;

    public Dog(String name) {
        this.name = name;
    }

    public String getName() { return this.name; }

    // 4. Polymorphism: Override abstract contract method
    @Override
    public void makeSound() {
        System.out.println(name + " says: Woof!");
    }
}

Line-by-Line Breakdown:

  • interface Animal { void makeSound(); }: Defines an abstract contract. Any class that implements Animal MUST implement makeSound().
  • private String name;: Encapsulates the variable so external classes cannot bypass setter validation or corrupt internal state.
  • @Override public void makeSound(): Implements Polymorphism. When you call makeSound() on an Animal reference pointing to a Dog object, Java dynamically binds the execution to the Dog's version at runtime.

💬 Topic Interview Prep Q&A

Meta Netflix

Q1: What is runtime polymorphism, and how does Java achieve it?

A: Runtime polymorphism (dynamic method dispatch) is when a call to an overridden method is resolved at runtime rather than compile-time. Java achieves this by referencing the actual object type in Heap memory using Virtual Method Tables (VTABLES) instead of relying on the reference variable type.

Google

Q2: Why doesn't Java support multiple inheritance of classes?

A: To prevent the Diamond Problem, which occurs when a subclass inherits conflicting implementations of a method from two different parent classes. Java bypasses this conflict by allowing multiple inheritance only through Interfaces (which do not hold instances or state).
