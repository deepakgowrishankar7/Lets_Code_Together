JVM Memory & Garbage Collection

Advanced Read Time: 12 mins

1. The Real-World Analogy: Desk Workspace vs. Central Warehouse

Imagine working in a busy logistics company:

  • Your Desk Workspace (Stack): A small, private desk. When you work on a task, you write notes, use local tools, and compile frames. When you finish the task, you instantly wipe the desk clean. It is fast, private, but limited in size.
  • The Central Warehouse (Heap): A massive, shared storage room. If you buy a huge container of goods (Object), you store it in the warehouse, and write down its address (reference) on your desk. Everyone can access the warehouse, and it needs a specialized cleaner (Garbage Collector) to sweep out boxes that are no longer referenced.

2. Stack Memory vs. Heap Memory

Property Stack Memory Heap Memory
Definition Stores method execution frames, local primitives, and object reference variables. Stores all instantiated objects and arrays.
Access scope Private to each individual thread (Thread-safe). Shared globally across all threads in the application.
Lifecycle Automatic (Pushed when method is called, popped when method returns). Managed by the Garbage Collector (Removes objects when they lose references).
Error Type java.lang.StackOverflowError (Deep recursion). java.lang.OutOfMemoryError (Running out of Heap space).

⚠️ Warning: Memory Leaks in Java!

Even though Java has an automatic Garbage Collector, you can still experience **Memory Leaks**. If you hold onto references to unused objects (e.g. adding objects to static lists or caching data without timeouts), the Garbage Collector cannot clean them up, eventually triggering an OutOfMemoryError.

3. How Garbage Collection (GC) Works

Garbage Collection is a daemon thread run by the JVM to clean up Heap memory. The process uses a **generational hypothesis** (most objects die young) and divides the Heap into pools:

  1. Young Generation: Newly created objects land in the **Eden space**. When it gets full, a minor GC runs, moving survivors to **Survivor spaces (S0, S1)**.
  2. Old (Tenured) Generation: Objects that survive multiple rounds of minor GC are promoted to the Old Generation, which stores long-lived objects. When this gets full, a Major/Full GC runs (causing "Stop the World" pauses).

GC identifies dead objects using **Reachability Analysis** starting from predefined **GC Roots** (like local variables, active threads, and static references). Any object not reachable from a GC root is collected.

💻 Example Code: Stack overflow simulation

public class MemoryDemo {
    public static void recursiveCall(int num) {
        // Deep recursion with no exit condition
        recursiveCall(num + 1); // Triggers StackOverflowError
    }

    public static void main(String[] args) {
        // Local primitive 'x' is pushed to the Stack frame of main
        int x = 50; 
        
        // Reference variable 'list' sits on Stack, pointing to ArrayList on Heap
        java.util.List<Object> list = new java.util.ArrayList<>();
        
        recursiveCall(1);
    }
}

💬 Topic Interview Prep Q&A

Uber Google

Q1: Describe StackOverflowError vs. OutOfMemoryError in Java.

A: StackOverflowError occurs when the JVM's call stack size limit is exceeded (typically due to infinite recursion or excessively deep method calls). OutOfMemoryError occurs when the Heap memory runs out of space to allocate new objects and the Garbage Collector cannot reclaim any more memory.

Amazon

Q2: What are GC Roots in Java?

A: GC Roots are starting points from which reachability analysis begins. Examples include active local variables on thread stacks, JNI (Java Native Interface) global references, and active static variables inside classes.
