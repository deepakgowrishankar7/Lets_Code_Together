JVM Architecture & Memory Management

The Java Virtual Machine (JVM) is the execution engine for Java applications. Understanding JVM architecture, memory allocation, and Garbage Collection (GC) is vital for writing high-performance Java code.

1. Architecture of JVM

The JVM is composed of three main subsystems:

  1. ClassLoader Subsystem: Loads, links, and initializes .class files.
  2. Runtime Data Areas (Memory): Allocates memory for program execution.
  3. Execution Engine: Executes bytecode via Interpreter, JIT Compiler, and Garbage Collector.

2. JVM Runtime Memory Structure

The JVM runtime memory is divided into five key regions:

Memory Region Scope Description
Heap Memory Shared by all threads Stores all instantiated objects and instance variables. Divided into Young Generation (Eden, Survivor spaces) and Old Generation.
Stack Memory Per-thread Stores local variables, method call frames, and primitive values. Destroyed when method execution ends.
Metaspace Shared by all threads Replaced PermGen in Java 8. Stores class metadata, static fields, and method bytecode. Allocates from native memory.
PC Registers Per-thread Holds the address of the currently executing JVM instruction for each thread.
Native Method Stack Per-thread Contains native method information (C/C++ native code execution).

3. Garbage Collection (GC) Mechanics

Garbage Collection is the automatic process of identifying and reclaiming unreferenced memory from Heap space to prevent OutOfMemory errors.

GC Process: Mark, Sweep, and Compact

  1. Mark: Identifies which objects are still in use (reachable from GC Roots) and which are unreferenced.
  2. Sweep: Removes unreferenced objects.
  3. Compact: Moves remaining live objects together to eliminate memory fragmentation.

Popular Java Garbage Collectors

  • Serial GC: Single-threaded collector designed for small applications.
  • Parallel GC: Multi-threaded collector focusing on throughput.
  • G1 GC (Garbage-First): Low-latency collector default in modern Java (Java 9+).
  • ZGC / Shenandoah: Ultra-low latency collectors for large heap sizes (gigabytes to terabytes) with pause times under 1 millisecond.

4. Memory Leaks in Java & Prevention

Even with Garbage Collection, memory leaks occur when unneeded objects remain reachable through strong references.

Common Causes of Memory Leaks:

  • Unclosed connections, I/O streams, or readers.
  • Static variables holding references to large objects or collections indefinitely.
  • Unregistered event listeners or callbacks.
  • Incorrect equals() and hashCode() in HashMap keys.
