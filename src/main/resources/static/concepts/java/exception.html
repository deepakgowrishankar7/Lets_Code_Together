Exception Handling

Intermediate Read Time: 10 mins

1. The Real-World Analogy: Car Airbags

Imagine driving a car down the road. If a tire blows out or another vehicle crashes into you, the car's airbags automatically inflate. The crash is an unexpected interruption, but the airbags deploy to mitigate damage and prevent a fatal accident.

In Java, an Exception is that unexpected crash (e.g. division by zero, database disconnected). Exception Handling is the airbag system, catching the error and allowing your program to recovery gracefully instead of abruptly crashing.

2. Exception Hierarchy: Checked vs. Unchecked

All exception classes inherit from java.lang.Throwable. Throwable splits into two main branches:

  • Checked Exceptions: Checked at compile-time. The compiler forces you to handle them (e.g., IOException, SQLException) using try-catch blocks or declaring them in method signatures using throws.
  • Unchecked Exceptions (Runtime Exceptions): Not checked at compile-time. Usually caused by programming logic errors (e.g., NullPointerException, ArrayIndexOutOfBoundsException).
  • Errors: Severe conditions outside the program's control (e.g., OutOfMemoryError, StackOverflowError). Programs should not try to catch Errors.

⚠️ Warning: Generic Exception Catching!

Avoid catching the top-level Exception class (e.g. catch (Exception e)) blindly. This hides unexpected bugs and makes debugging extremely difficult. Always catch the most specific exception first.

3. The Try-Catch-Finally Mechanism

Errors are captured and resolved inside try-catch wrappers:

  • try: Surrounds the code that might throw an exception.
  • catch: Executes if an exception is thrown inside the try block, handling the error.
  • finally: A block that **always executes**, regardless of whether an exception was thrown or caught (essential for closing files, network connections, or database sockets).

💻 Example Code & Line-by-Line Breakdown

import java.io.*;

public class ExceptionDemo {
    public static void readFile(String path) throws IOException {
        FileReader file = new FileReader(path); // Might throw FileNotFoundException
        BufferedReader fileInput = new BufferedReader(file);
        
        try {
            System.out.println(fileInput.readLine());
        } finally {
            // Always close resources to prevent memory leaks
            System.out.println("Closing resources...");
            fileInput.close();
        }
    }
}

Line-by-Line Breakdown:

  • throws IOException: Declares that this method does not handle IO exceptions internally. Instead, it delegates responsibility to whatever method calls readFile().
  • try { ... } finally { fileInput.close(); }: Ensures that the file reader is closed safely even if reading the line fails midway.

💬 Topic Interview Prep Q&A

Amazon Uber

Q1: What happens if you return a value from a try block? Does the finally block still run?

A: Yes. The finally block always executes. If there is a return statement inside the try block, the JVM saves the return value, executes the finally block first, and then returns the saved value. If the finally block also contains a return statement, it will override the value returned in the try block.

Microsoft

Q2: What is the difference between throw and throws?

A: throw is a keyword used inside methods to explicitly instantiate and throw a specific exception (e.g. throw new IllegalArgumentException();). throws is a keyword in the method header used to declare that this method might throw specific checked exceptions, warning callers to handle them.
