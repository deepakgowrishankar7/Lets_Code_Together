Java Database Connectivity (JDBC)

JDBC is a Java API that defines how a client application may access a relational database. It provides methods to query and update data in a database using SQL statements.

1. Architecture & Steps to Connect JDBC

Connecting Java to a database involves 5 standard steps:

  1. Register Driver: Load the database driver (`Class.forName("org.h2.Driver")` or automatic loading).
  2. Create Connection: `DriverManager.getConnection(url, username, password)`
  3. Create Statement: Create `Statement` or `PreparedStatement`.
  4. Execute Query/Update: Execute SQL (`executeQuery` or `executeUpdate`).
  5. Close Connection: Close resources using try-with-resources.

2. `PreparedStatement` vs `Statement`

Always prefer PreparedStatement over Statement. PreparedStatement pre-compiles SQL queries, boosts execution speed for repeated queries, and prevents SQL Injection attacks. 

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class JdbcExample {
    private static final String URL = "jdbc:h2:mem:testdb";
    private static final String USER = "sa";
    private static final String PASS = "";

    public static void main(String[] args) {
        String sql = "SELECT id, username, email FROM users WHERE role = ?";

        // Use try-with-resources for automatic closing of Connection, Statement, and ResultSet
        try (Connection conn = DriverManager.getConnection(URL, USER, PASS);
             PreparedStatement stmt = conn.prepareStatement(sql)) {

            // Bind parameter
            stmt.setString(1, "ADMIN");

            try (ResultSet rs = stmt.executeQuery()) {
                while (rs.next()) {
                    int id = rs.getInt("id");
                    String username = rs.getString("username");
                    String email = rs.getString("email");

                    System.out.println("User [" + id + "]: " + username + " (" + email + ")");
                }
            }

        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

3. Transaction Management (`commit`, `rollback`)

By default, JDBC connections operate in auto-commit mode (every individual SQL statement is treated as a transaction). For atomic multi-step operations (e.g. money transfers), disable auto-commit. 

public void transferMoney(Connection conn, int fromAcc, int toAcc, double amount) throws SQLException {
    try {
        // Step 1: Disable Auto-Commit
        conn.setAutoCommit(false);

        // Step 2: Deduct money from account A
        PreparedStatement deduct = conn.prepareStatement("UPDATE accounts SET balance = balance - ? WHERE id = ?");
        deduct.setDouble(1, amount);
        deduct.setInt(2, fromAcc);
        deduct.executeUpdate();

        // Step 3: Add money to account B
        PreparedStatement add = conn.prepareStatement("UPDATE accounts SET balance = balance + ? WHERE id = ?");
        add.setDouble(1, amount);
        add.setInt(2, toAcc);
        add.executeUpdate();

        // Step 4: Commit Transaction if everything succeeded
        conn.commit();
        System.out.println("Transaction committed successfully!");

    } catch (Exception e) {
        // Step 5: Rollback Transaction on error
        conn.rollback();
        System.err.println("Transaction failed! Changes rolled back.");
    } finally {
        conn.setAutoCommit(true);
    }
}

4. Connection Pooling (HikariCP Overview)

Opening and closing physical database connections is expensive. In production systems, Connection Pools (such as HikariCP or Apache DBCP) maintain a pool of reusable connections, eliminating connection latency.
