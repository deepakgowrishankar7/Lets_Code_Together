SQL Advanced Queries

Advanced SQL techniques help you write powerful, efficient queries for real-world data problems.

Views

A view is a saved query that behaves like a virtual table.

CREATE VIEW active_customers AS
SELECT id, name, email
FROM customers
WHERE active = TRUE;

SELECT *
FROM active_customers;

Common Table Expressions (CTEs)

CTEs make complex queries easier to read by creating named temporary result sets.

WITH sales_by_dept AS (
  SELECT department_id,
         SUM(amount) AS total_sales
  FROM sales
  GROUP BY department_id
)
SELECT d.name, s.total_sales
FROM sales_by_dept s
JOIN departments d ON d.id = s.department_id;

Window Functions

Window functions perform calculations across rows related to the current row.

SELECT employee_id,
       department_id,
       salary,
       AVG(salary) OVER (PARTITION BY department_id) AS avg_dept_salary,
       RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS salary_rank
FROM employees;

CASE Expressions

Use CASE to apply conditional logic inside queries.

SELECT name,
       salary,
       CASE
         WHEN salary >= 100000 THEN 'High'
         WHEN salary >= 60000 THEN 'Medium'
         ELSE 'Low'
       END AS salary_band
FROM employees;

Set Operators

Combine query results using UNION, INTERSECT, and EXCEPT.

SELECT email FROM users
UNION
SELECT email FROM newsletter_subscribers;

Recursive Queries

Use recursive CTEs to traverse hierarchical data, such as organizational charts.

WITH RECURSIVE team_hierarchy AS (
  SELECT id, manager_id, name, 1 AS level
  FROM employees
  WHERE manager_id IS NULL
  UNION ALL
  SELECT e.id, e.manager_id, e.name, th.level + 1
  FROM employees e
  JOIN team_hierarchy th ON e.manager_id = th.id
)
SELECT *
FROM team_hierarchy;

Performance Tips

  • Use indexes on columns used in WHERE, JOIN, and ORDER BY.
  • Prefer CTEs for readability, but test execution plans for performance.
  • Keep queries simple and break complex logic into smaller steps when possible.
