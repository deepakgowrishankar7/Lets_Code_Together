SQL vs NoSQL & JSON in Relational Databases

Modern RDBMS engines (MySQL 8+, PostgreSQL, SQL Server) support native JSON Data Types, bridging the gap between structured relational tables and flexible document storage.

1. Relational (SQL) vs Document (NoSQL) Comparison

Aspect SQL (Relational) NoSQL (Document / Key-Value)
Schema Pre-defined, rigid schema with tables & columns Dynamic, schema-less (JSON/BSON documents)
ACID Compliance Strong transactional consistency (ACID) BASE model (Eventually consistent / Tunable)
Scaling Vertical scaling (CPU/RAM) & Read Replicas Horizontal scaling across sharded clusters

2. Storing & Querying JSON in SQL

You can store unstructured or semi-structured data directly inside a table column marked as JSON or JSONB.

-- Create table with JSON column
CREATE TABLE user_profiles (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50),
    attributes JSON
);

-- Insert JSON documents
INSERT INTO user_profiles (username, attributes) 
VALUES (
    'sarah_dev', 
    '{"age": 28, "skills": ["SQL", "Java", "Docker"], "settings": {"theme": "dark", "notifications": true}}'
);

3. Extracting JSON Fields with Functions (`->>`, `JSON_EXTRACT`)

-- Extract JSON fields using shorthand operators (PostgreSQL / MySQL)
SELECT 
    username,
    attributes->>'$.age' as age,
    attributes->>'$.settings.theme' as theme
FROM user_profiles
WHERE attributes->>'$.settings.notifications' = 'true';
Expected Output: 
+-----------+-----+-------+
| username  | age | theme |
+-----------+-----+-------+
| sarah_dev | 28  | dark  |
+-----------+-----+-------+

4. Functional Indexes on JSON Fields

You can create B-Tree indexes on specific JSON paths to speed up lookups over millions of JSON documents:

-- Create index on nested JSON field
CREATE INDEX idx_user_theme ON user_profiles ((CAST(attributes->>'$.settings.theme' AS CHAR(10))));
