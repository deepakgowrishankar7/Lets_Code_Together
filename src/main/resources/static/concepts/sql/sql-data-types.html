SQL Data Types

Data types tell the database what kind of values a column can store. Choosing the right type keeps your data accurate, efficient, and easy to query.

Why Data Types Matter

Good column types improve performance, prevent bad data, and help the database optimize storage. They also make queries behave predictably.

Numeric Types

  • INT — whole numbers like 1, 42, -7.
  • SMALLINT — smaller whole numbers for less storage.
  • DECIMAL(p, s) — exact decimal values, good for money. DECIMAL(10,2) stores up to 10 digits with 2 after the decimal.
  • FLOAT / REAL — approximate numbers for scientific data, not ideal for money.

Text Types

  • CHAR(n) — fixed-length strings. Always stored with exactly n characters.
  • VARCHAR(n) — variable-length strings. Use this for names, emails, and flexible text.
  • TEXT — long text, such as articles or comments.

Date and Time Types

  • DATE — calendar dates like '2026-06-05'.
  • TIME — time of day like '14:30:00'.
  • DATETIME / TIMESTAMP — date and time together.

Special Types

  • BOOLEAN — true or false values.
  • ENUM — a fixed set of values, such as 'small', 'medium', 'large'.
  • JSON — structured JSON data inside a column.
  • BLOB — binary data such as images or files.

NULL vs Empty

NULL means unknown or missing data. It is different from an empty string ('') or zero (0).

Practical Example

CREATE TABLE products (
  product_id INT PRIMARY KEY,
  name VARCHAR(120) NOT NULL,
  category VARCHAR(50),
  price DECIMAL(8, 2) NOT NULL,
  in_stock BOOLEAN DEFAULT TRUE,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

Choosing the Right Type

  • Use INT for counts and IDs.
  • Use DECIMAL for money so values stay exact.
  • Use VARCHAR for names and text fields that change size.
  • Use DATE or DATETIME for times and dates.

Type Comparison

CHAR always uses fixed storage, while VARCHAR uses only as much space as needed. Use CHAR for codes of fixed length, like country codes.
