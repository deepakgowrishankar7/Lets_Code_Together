SQL Triggers & Database Events

A Trigger is a special type of stored program that automatically executes (fires) when a specific event (`INSERT`, `UPDATE`, or `DELETE`) occurs on a table or view.

1. Types of Triggers

  • BEFORE Trigger: Fires before the data operation is written to disk (used for data validation or default values).
  • AFTER Trigger: Fires after the data operation completes (used for auditing, logging, or notifications).
  • INSTEAD OF Trigger: Replaces standard DML execution (commonly used on views).

2. Creating an Audit Log Trigger (`AFTER INSERT`)

-- Step 1: Create Audit Table
CREATE TABLE audit_logs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    action_type VARCHAR(20),
    user_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Step 2: Create Trigger for New User Registrations
DELIMITER //

CREATE TRIGGER trg_user_after_insert
AFTER INSERT ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_logs (action_type, user_id)
    VALUES ('USER_REGISTERED', NEW.id);
END //

DELIMITER ;

3. Data Validation Trigger (`BEFORE UPDATE`)

Using pseudo-records NEW (new value) and OLD (previous value): 

-- Prevent updating balance below zero
DELIMITER //

CREATE TRIGGER trg_prevent_negative_balance
BEFORE UPDATE ON accounts
FOR EACH ROW
BEGIN
    IF NEW.balance < 0 THEN
        SIGNAL SQLSTATE '45000' 
        SET MESSAGE_TEXT = 'Error: Account balance cannot be negative.';
    END IF;
END //

DELIMITER ;

4. Best Practices for Database Triggers

  • Keep trigger logic lightweight to avoid cascading locks and performance slowdowns.
  • Avoid recursive trigger loops (e.g. Trigger A updates Table B which triggers Table A).
  • Document triggers thoroughly as they execute transparently behind the scenes.
