SQL Stored Procedures & Functions

Stored Procedures and User-Defined Functions (UDFs) are reusable SQL code blocks compiled and stored on the database server for execution efficiency and modularity.

1. Stored Procedures (`CREATE PROCEDURE`)

Procedures can perform complex transactions, accept input (`IN`) and output (`OUT`) parameters, and execute procedural code. 

-- MySQL Stored Procedure Example
DELIMITER //

CREATE PROCEDURE ProcessOrder(
    IN p_customer_id INT,
    IN p_amount DECIMAL(10,2),
    OUT p_status VARCHAR(50)
)
BEGIN
    DECLARE v_balance DECIMAL(10,2);

    -- Get current customer balance
    SELECT balance INTO v_balance 
    FROM accounts 
    WHERE customer_id = p_customer_id;

    IF v_balance >= p_amount THEN
        -- Deduct balance & create order
        UPDATE accounts SET balance = balance - p_amount WHERE customer_id = p_customer_id;
        INSERT INTO orders(customer_id, amount) VALUES (p_customer_id, p_amount);
        SET p_status = 'SUCCESS';
    ELSE
        SET p_status = 'INSUFFICIENT_FUNDS';
    END IF;
END //

DELIMITER ;

Calling a Stored Procedure:

CALL ProcessOrder(101, 250.00, @order_status);
SELECT @order_status; -- Returns 'SUCCESS' or 'INSUFFICIENT_FUNDS'

2. User-Defined Functions (`CREATE FUNCTION`)

Functions return a single scalar value or a table result and can be invoked directly inside SELECT statements. 

-- Function to calculate tax on an amount
CREATE FUNCTION CalculateTax(amount DECIMAL(10,2), tax_rate DECIMAL(4,2))
RETURNS DECIMAL(10,2)
DETERMINISTIC
BEGIN
    RETURN amount * (tax_rate / 100);
END;

-- Using Function in a SELECT query
SELECT order_id, amount, CalculateTax(amount, 18.0) as gst_amount
FROM orders;

3. Stored Procedures vs Functions

Feature Stored Procedure Function
Invocation Called using CALL or EXEC Used inside SELECT statements
Return Value Can return 0, 1, or multiple parameters (`OUT`) Must return exactly one scalar or table value
Transactions Can start, commit, or rollback transactions Cannot manage transactions inside functions
