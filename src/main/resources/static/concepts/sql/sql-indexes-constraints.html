SQL Indexes and Constraints

Indexes and constraints help the database enforce rules and find rows quickly. They are essential for reliable, high-performance SQL.

Primary Key

A primary key uniquely identifies each row.

CREATE TABLE employees (
  id INT PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(150)
);

Unique Constraint

Ensures values are unique in a column.

CREATE TABLE products (
  product_id INT PRIMARY KEY,
  sku VARCHAR(50) UNIQUE,
  name VARCHAR(120)
);

NOT NULL and DEFAULT

Require values and provide defaults.

CREATE TABLE users (
  id INT PRIMARY KEY,
  username VARCHAR(80) NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

Check Constraint

Limits values based on a condition.

CREATE TABLE transactions (
  id INT PRIMARY KEY,
  amount DECIMAL(10,2) CHECK (amount > 0),
  status VARCHAR(20) CHECK (status IN ('pending', 'paid', 'cancelled'))
);

Foreign Key

Ensures relationships between tables stay valid.

CREATE TABLE orders (
  id INT PRIMARY KEY,
  customer_id INT,
  order_date DATE,
  FOREIGN KEY (customer_id) REFERENCES customers(id)
);

Indexes

Indexes speed up search and join operations.

CREATE INDEX idx_customer_email
ON customers (email);

CREATE INDEX idx_orders_customer_date
ON orders (customer_id, order_date);

When to Use Indexes

Index columns that are frequently searched, joined, or sorted. Avoid indexing every column because each index slows writes.
