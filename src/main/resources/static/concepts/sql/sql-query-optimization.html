SQL Query Optimization & Performance Tuning

Query optimization is the process of writing and tuning SQL queries so that the database engine executes them with minimal CPU, memory, and I/O overhead.

1. Reading Execution Plans with `EXPLAIN`

Prepend EXPLAIN or EXPLAIN ANALYZE before any SELECT query to see how the database optimizer executes it. 

EXPLAIN ANALYZE 
SELECT * FROM orders WHERE customer_id = 450 AND order_date >= '2026-01-01';
Key Terms to Look For:
  • Full Table Scan (ALL / Seq Scan): Reads every single row from disk (slow on large tables!).
  • Index Scan / Index Lookup: Uses a B-Tree index to jump directly to matching rows (fast!).
  • Filter / Rows Examined: Shows how many rows were checked vs returned.

2. Writing SARGable Queries (Search Argument Able)

A query is SARGable if the query engine can use an index. Applying functions directly to columns in the WHERE clause destroys index usage! 

-- ❌ NON-SARGable (Index Disabled due to YEAR() function):
SELECT * FROM orders WHERE YEAR(order_date) = 2026;

-- ✅ SARGable (Index Enabled using Range comparison):
SELECT * FROM orders WHERE order_date >= '2026-01-01' AND order_date < '2027-01-01';

3. Avoiding `SELECT *` & N+1 Query Problems

  • Select Only Required Columns: Reduces network bandwidth, memory, and allows Covering Index optimization.
  • Avoid N+1 Queries: Use JOIN or bulk IN (...) queries instead of making N database calls in a loop from code.
-- ❌ Bad: Selecting all columns when only name & email needed
SELECT * FROM users WHERE status = 'ACTIVE';

-- ✅ Good: Specific columns
SELECT id, username, email FROM users WHERE status = 'ACTIVE';

4. Covering Indexes

A Covering Index contains all the fields requested by the query, allowing the database to fulfill the query purely from index RAM without touching table disk blocks! 

-- Composite index on (department_id, salary)
CREATE INDEX idx_dept_salary ON employees(department_id, salary);

-- Index covers the query completely!
SELECT department_id, AVG(salary) 
FROM employees 
GROUP BY department_id;
