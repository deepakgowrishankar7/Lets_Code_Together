SQL Normalization

Normalization organizes data into tables so it is clean, consistent, and easy to maintain.

Why Normalize?

Normalization prevents duplicate data, reduces errors, and makes updates safer.

First Normal Form (1NF)

A table is in 1NF when each column has atomic values and each row is unique.

CREATE TABLE orders (
  id INT PRIMARY KEY,
  order_date DATE,
  customer_id INT
);

Second Normal Form (2NF)

2NF means the table is in 1NF and every non-key column depends on the whole primary key.

Third Normal Form (3NF)

3NF means the table is in 2NF and non-key columns depend only on the primary key, not on other non-key columns.

Boyce-Codd Normal Form (BCNF)

BCNF is a stricter version of 3NF that removes remaining dependency issues.

Normalization Example

Bad design with duplicate data:

order_id | customer_name | customer_email | product_name | product_price

Better design with normalized tables:

CREATE TABLE customers (
  id INT PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(100)
);

CREATE TABLE products (
  id INT PRIMARY KEY,
  name VARCHAR(100),
  price DECIMAL(8,2)
);

CREATE TABLE orders (
  id INT PRIMARY KEY,
  customer_id INT,
  order_date DATE,
  FOREIGN KEY (customer_id) REFERENCES customers(id)
);

CREATE TABLE order_items (
  order_id INT,
  product_id INT,
  quantity INT,
  PRIMARY KEY (order_id, product_id),
  FOREIGN KEY (order_id) REFERENCES orders(id),
  FOREIGN KEY (product_id) REFERENCES products(id)
);

When to Denormalize

Denormalization can improve read performance in large data systems but may increase redundancy. Use it only when necessary for performance.
