SQL Database Security & Permissions

Database Security involves controlling access rights, enforcing Principle of Least Privilege, preventing SQL Injection, and protecting sensitive data.

1. User Management & Granting Permissions (`GRANT`, `REVOKE`)

-- Create a database user
CREATE USER 'app_developer'@'%' IDENTIFIED BY 'SecurePass#2026';

-- Grant specific privileges on specific database
GRANT SELECT, INSERT, UPDATE ON mydatabase.* TO 'app_developer'@'%';

-- Apply privilege changes
FLUSH PRIVILEGES;

-- Revoke dangerous DELETE permission
REVOKE DELETE ON mydatabase.* FROM 'app_developer'@'%';

2. Preventing SQL Injection Attacks

SQL Injection (SQLi) occurs when untrusted user inputs are concatenated directly into raw SQL strings, allowing attackers to manipulate queries. 

-- ❌ VULNERABLE SQL String (Malicious input: "admin' OR '1'='1")
String sql = "SELECT * FROM users WHERE username = '" + userInput + "'";
// Resulting query: SELECT * FROM users WHERE username = 'admin' OR '1'='1' (Bypasses authentication!)

-- ✅ SECURE SQL: Prepared Statements / Parameterized Queries
PreparedStatement stmt = conn.prepareStatement("SELECT * FROM users WHERE username = ?");
stmt.setString(1, userInput); // Input treated strictly as literal data!

3. Row-Level Security (RLS)

Row-Level Security restricts which rows a user can access based on security policies (supported in PostgreSQL and SQL Server). 

-- PostgreSQL Row Level Security Example
ALTER TABLE tenant_data ENABLE ROW LEVEL SECURITY;

-- Create policy allowing users to see only their tenant data
CREATE POLICY tenant_isolation_policy ON tenant_data
    USING (tenant_id = CURRENT_SETTING('app.current_tenant'));

4. Data Encryption & Obfuscation

  • Encryption at Rest: Encrypting database files and backups on disk (TDE - Transparent Data Encryption).
  • Hashing Sensitive Data: Storing passwords as salted cryptographic hashes (BCrypt/Argon2) rather than plaintext.
